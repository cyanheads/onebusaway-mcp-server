# 0.1.15 — 2026-09-19

## Added

- **Upstream request pacing** (#25) — Every OneBusAway call runs through a FIFO pacer sized to the shared API-key budget (`ONEBUSAWAY_RATE_LIMIT_REQUESTS` / `ONEBUSAWAY_RATE_LIMIT_WINDOW_MS` / `ONEBUSAWAY_RATE_LIMIT_MAX_WAIT_MS`, defaults 20 / 60000 / 45000). A call that cannot get a slot within the wait cap fails `rate_limited` with `retryable: true` and `data.retryAfter` instead of spending an upstream request, an upstream 429 pauses every queued call, and all 15 tools now declare the `rate_limited` contract (previously only `onebusaway_get_arrivals`, as `retryable: false`). `ctx.signal` cancels a call while it waits in the queue; `createApp({ teardown })` disposes the pacer on shutdown.

## Changed

- **Session posture** (mcp-ts-core 0.13.1) — `createApp` declares `sessionMode: 'stateless'`; an exported `MCP_SESSION_MODE` still wins whenever it carries a meaningful value — an empty or unsubstituted `${…}` value reads as unset. The value `stateless` in `.env.example`, the Docker image, and the README was already set in 0.1.14 — this release only aligns the `.env.example` comment block with the framework template and adds the `src/` declaration.
- **Argument rejections** (mcp-ts-core 0.12.7, 0.13.3) — An argument rejection carries `structuredContent.error` with code `-32602`, `data.reason: "invalid_arguments"`, and a `Recovery:` hint naming the accepted keys.
- **Error text** (mcp-ts-core 0.13.5) — Every tool error's text closes with `(reason <reason>)`, adding ` · retryable` or ` · not retryable` only when the contract entry declares `retryable`.
- **Pre-validation** (mcp-ts-core 0.13.4) — Tool arguments drop client-added root keys and rewrite a case-style alias of a declared key before validation; `inputSchema` is byte-identical.
- **Server card** (mcp-ts-core 0.13.2) — `/.well-known/mcp.json` publishes the resolved session mode under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]`.
- **Shutdown** (mcp-ts-core 0.13.1) — `SIGTERM`/`SIGINT` end the process explicitly, exiting 0 under both Bun and Node.
- **Skill tree** (mcp-ts-core 0.13.0) — Moved from `skills/` to `framework-skills/`, so a plugin install no longer receives development skills. Bun engines floor raised to `>=1.4.0`.
- **Schema rendering** — Nullable output fields are advertised as `type: [<type>, "null"]` instead of an `anyOf` — a rendering change from `zod` ^4.4.3 → ^4.6.5 with no semantic difference.
