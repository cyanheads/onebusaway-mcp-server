# 0.1.11 — 2026-07-12

## Added

- **Not-found discovery hints** — `notFoundData()` attaches a `data.recovery.hint` naming the tool that yields a valid ID, keyed by contract reason: `stop_not_found`, `route_not_found`, `agency_not_found`, `trip_not_found`, `block_not_found`, `situation_not_found`. The framework mirrors `data.recovery.hint` into the client's `content[]` text automatically. (#17)
- **Supply-chain install guard** — `bunfig.toml` gains `minimumReleaseAge = 259200` (3-day hold on freshly published package versions; existing `bun.lock` entries are unaffected) with `minimumReleaseAgeExcludes` for `@cyanheads/mcp-ts-core` (first-party, adopted same-day), plus `[install.security] scanner = "@socketsecurity/bun-security-scanner"` scanning every package for malware, typosquats, and CVEs before install (the scanner package is added to `devcheck.config.json`'s `depcheck` ignores). `scripts/devcheck.ts`'s Outdated gate now treats a version held back by the release-age guard (bun marks it `*`, Update equal to Current) as nothing to adopt — a genuine update still fails the gate.
- **`.github/SECURITY.md`** — disclosure policy: private reports via the GitHub Security tab or casey@caseyjhand.com, fixes ship on the latest release.
- **`.github/FUNDING.yml`** and **`.gitattributes`** — funding links (`github`, `buy_me_a_coffee`); LF normalization, binary-asset markers, and `linguist-generated` markers for `bun.lock`, `CHANGELOG.md`, and `docs/tree.md`.

## Fixed

- **`onebusaway_get_arrivals` rate-limit retries** — `RateLimitError` classification now sets `data.retryable: false`, and the `get_arrivals` tool's `rate_limited` contract flips `retryable: true` → `false`, so clients stop auto-retrying a 429 that a single shared upstream API key makes a global budget, not a per-caller quota; the error message states this explicitly instead of implying a personal "per IP" limit. The stale `maxRetries: 0` comment (claiming `withRetry` wraps these calls, when nothing did) is corrected. (#16)
- **Null `resp.data` crashes reported as `ServiceUnavailable` instead of `NotFound`** — eight ID-lookup methods (`getRoute`, `getArrivals`, `getTrip`, `getVehicles`, `getScheduleForStop`, `getScheduleForRoute`, `getBlock`, `getAlert`) now guard the SDK's null-resolve response and throw a clean `NotFound` carrying the matching reason, instead of dereferencing `resp.data` into a raw `TypeError` that fell through to a `ServiceUnavailable` catch-all. Three location/list-query methods with no single ID to attach (`listAgencies`, `findStops`, `findRoutes`) throw `ServiceUnavailable` instead — never a `NotFound` with no `reason`. `getStop` and `listRoutesForAgency` (already guarded) are refactored onto the same `notFoundData()` helper. Follow-through on `#2`'s "apply broadly" note. (#22)
