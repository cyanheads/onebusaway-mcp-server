# 0.2.1 — 2026-10-08

Framework upgrade `@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.14. Callers gain accepted inputs.

## Changed

- **Numeric and boolean strings** (cyanheads/mcp-ts-core#707, framework 0.13.14) — A numeric string sent to a number or integer field (`"5"` for `maxCount`, `"300"` for `radius`) and a boolean string sent to `includeSchedule` are accepted.
- **`null` optionals** (cyanheads/mcp-ts-core#616, framework 0.13.14) — `null` at an optional key is treated as absent, so its default applies.
- **Integers for string fields** (cyanheads/mcp-ts-core#487, framework 0.13.9) — An integer sent to a string field is converted to its digits before validation (`agencyId: 1` → `"1"`).
- **Request IDs on tool errors** (cyanheads/mcp-ts-core#576, framework 0.13.10) — A tool error result's text ends with `request <id>`, and `error.data.requestId` carries the same id.
- **MCP SDK 2.1 transport behavior** (framework 0.13.9, `@modelcontextprotocol/server` 2.1) — A 2026-07-28 POST without `MCP-Protocol-Version` is refused `400` / `-32020`, a JSON-RPC batch of more than 100 messages is refused, and on stdio, stdin EOF aborts requests still in flight. A client relying on the old answers sees different ones.
- **OTLP export** (framework 0.13.7) — With `OTEL_ENABLED=true`, `OTEL_EXPORTER_OTLP_ENDPOINT` alone exports traces and metrics to `<base>/v1/traces` and `<base>/v1/metrics`; with no endpoint set nothing is exported (it used to send metrics and logs to `localhost:4318`).
- **Docker image** — Production dependencies install in a `deps` stage on `$BUILDPLATFORM` with `--os`/`--cpu` cross-install, so multi-arch builds no longer run Bun under QEMU (framework 0.13.10 template). musl-only packages are pruned from the glibc image (framework 0.13.11 template). The Bun base images move 1.4.0 → 1.4.2, and `MCP_FORCE_CONSOLE_LOGGING`, which nothing read, is gone from the Dockerfile.
- **`.env.example`** — Documents `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, and the `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, `_METRICS_ENDPOINT`, and `_LOGS_ENDPOINT` overrides; the `OTEL_EXPORTER_OTLP_ENDPOINT` comment now describes a base URL.
- **Ignore rules** — `.gitignore` swaps `.env`, `.env.local`, and `.env.*.local` for `.env*` with `.env.example`, `.env.template`, and `.env.sample` kept; `.dockerignore` swaps its five `.env` entries for `.env*` and adds `.mcpregistry_github_token` and `.mcpregistry_registry_token`. `.mcpbignore` adds `/docs/idea.md`, `/logs/`, `/.cache/`, `/coverage/`, and `/tests/`.
- **`package.json`** — `files` excludes `dist/*.mcpb`, `keywords` gains `stdio` and `streamable-http`, and `packageManager` moves to `bun@1.4.2`.
- **CodeQL workflow** — `.github/workflows/codeql.yml` runs one job per language (`actions`, `javascript-typescript`), each uploading under the `/language:<language>` category.
- **Skills and scripts** — `framework-skills/` and `scripts/` re-synced from mcp-ts-core 0.13.14, adding `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` for the Docker `deps` stage.
- **Docs** — `CLAUDE.md` pins framework `^0.13.14` and MCP SDK `^2.2.0` and takes the template's updated sections; the README MCP SDK badge moves `^2.0.0` → `^2.2.0`.

## Fixed

- **`server.json` npm packages** (framework 0.13.11 template, cyanheads/mcp-ts-core#622) — Both npm package entries drop the `run start:*` arguments and set `runtimeHint: npx`, and the streamable-http entry sets `MCP_TRANSPORT_TYPE` to `http`, so a registry client launching it starts HTTP.
